# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Audionaut is a cross-platform (macOS / Windows / Linux) desktop audio editing application for multitrack recordings, built on the [JUCE](https://juce.com) C++ framework. All application code lives under `Audionaut/Source` in the `audium` namespace. The project is dual-licensed (GPL/commercial).

## Build

The IDE project files are **generated by the Projucer** from `Audionaut/Audionaut.jucer`. Do not hand-edit files under `Audionaut/Builds/` or `Audionaut/JuceLibraryCode/` — edit the `.jucer` in the Projucer and re-save to regenerate them (adding source files, modules, or preprocessor defines happens there). C++ standard is C++20.

- **Xcode**: open `Audionaut/Builds/MacOSX/Audionaut.xcodeproj`
- **Visual Studio 2022**: open `Audionaut/Builds/VisualStudio2022/Audionaut.sln`
- **Linux**: `cd Audionaut/Builds/LinuxMakefile/ && make CONFIG=Release -j8` (see README for the `apt` dependency list)

Clone/refresh submodules before building — the build links against them directly:
```
git submodule update --init --recursive
```

## Tests

Tests use **Catch2** and are built with CMake (separate from the app build). Run from the repo root:
```
cmake -B build -S Audionaut/Catch2Tests
cmake --build build
./build/AudionautTests_artefacts/AudionautTests          # run all tests
./build/AudionautTests_artefacts/AudionautTests "[essentia]"   # run one tag/scenario
```
Test sources live in `Audionaut/Catch2Tests/Tests/*.cpp`; scenarios are tagged (e.g. `[engine][essentia][segmentation]`) so you can filter by tag. Test audio/data lives in `Audionaut/Catch2Tests/TestFiles/` and is located at runtime via the `CURRENT_SOURCE_DIR` compile define. `Audionaut/Catch2Tests/CMakeLists.txt` globs engine/interface source directories — **a newly added Source subdirectory must be added to the `file(GLOB ...)` list there** or its `.cpp` files won't be compiled into the test binary.

CI (`.github/workflows/`) runs this same CMake build + `ctest` on macOS and Linux for pushes/PRs to `main` and `develop`.

## Essentia (audio analysis)

The `essentia` submodule is a **prebuilt static library** dependency, not built by CMake/Projucer. The test CMakeLists links `Submodules/essentia/build/src/libessentia.a` plus its 3rd-party `.a` files under `Submodules/essentia/packaging/debian_3rdparty/lib/`. If those artifacts are missing, essentia must be built first with its own waf-based build system (`Submodules/essentia/waf`, `wscript`) before analysis code will link. Essentia is the engine behind the analysis features (BIC segmentation, onset detection, beat tracking).

## Architecture

The app splits cleanly into **Engine** (audio/data/business logic, UI-agnostic) and **Interface** (JUCE GUI). The engine is unit-testable in isolation — the Catch2 target compiles engine + interface source but exercises mainly the engine.

### Composition root
`AudiumFactory::createAudiumEngine()` (`Engine/Factory/`) is the single place that constructs and wires the object graph. `AudiumEngine` is the central facade: it holds shared_ptrs to the major containers and is the entry point for project open/save. Dependencies are injected via constructor (shared_ptr), not created internally — follow this pattern when adding engine services.

### Engine subsystems (`Source/Engine/*`)
- **Group** — `AudioTrackContainer` / `AudioTrack`: the multitrack model. `AudioTrack` owns playlists and regions.
- **Channel**, **Playback** — audio routing and rendering: `AudioBusInterface`, `AudioBusRenderer`, `Voice`, `Playback`. This is the real-time audio path.
- **Core** — real-time-safe primitives: `LockFreeCommander`, `LockFreeContainer`, `DspClip`. Communication from the message thread to the audio thread must stay lock-free/allocation-free here; the `farbot` submodule provides the realtime-safe utilities.
- **Resource / Region / PlayList / Recording / Export / Undo / Selection / Provider / Analysis / AutoEdit** — the remaining feature containers, each a self-contained subsystem.
- **Link** — Ableton Link integration (`link` submodule) for tempo/transport sync.

### Persistence
Projects serialize through the `Streamable` interface (`Engine/Streamable.h`), which every persistable object implements: `writeToStream`/`readFromStream` (binary) and `writeToJson`/`readFromJson` (via nlohmann `json`, the `json` submodule). A project is a `.audium` document package (directory) containing the project file plus audio files. Serialization takes a `rebuild` flag to distinguish loading into a fresh graph vs. re-reading into an existing one.

### Interface (`Source/Interface/*`)
Standard JUCE layering: `Application` (app lifecycle, main window, menus, command IDs) → `Components` (panels: Header / Middle with Arrangement+Channel+Edit views / Right) → `Views`, `Controls`, `Widgets`, `Models` (JUCE list-box models), `Handlers` (zoom, snap-to-grid), `LookAndFeel`. The UI observes/commands the engine; keep audio logic in the engine, not in components.

## Conventions

- Everything is namespaced `audium`.
- Engine classes use `JUCE_DECLARE_NON_COPYABLE_WITH_LEAK_DETECTOR` and pass collaborators as references/shared_ptrs (dependency injection) rather than constructing them.
- Feature flags are compile-time defines set in the `.jucer` (e.g. `AUTO_EDIT_ENABLED`, `JUCE_MODAL_LOOPS_PERMITTED`), not runtime config.
- Source files carry the GPL/commercial license header; match it when creating new files.
